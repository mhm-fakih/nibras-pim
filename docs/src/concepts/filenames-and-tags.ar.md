# أسماء الملفات والوسوم

تحمل كل ملاحظة في نبراس بياناتها الوصفية **في اسم ملفها**. وهذا العُرف الواحد يتشاركه،
بايتًا ببايت، الهاتف وسطح المكتب والطرفية وتطبيق الويب والخادم.

## المخطط { #the-scheme }

```text
<timestamp>~<type>~p<priority>~<category>.md
```

```text
2026_06_10-143025~T~p2~A.md
│                 │  │  └─ category  A
│                 │  └──── priority  2
│                 └─────── type      T
└───────────────────────── timestamp 2026-06-10 14:30:25
```

| الحقل | الصيغة | ملاحظات |
|-------|--------|-------|
| timestamp (الطابع الزمني) | `yyyy_MM_dd-HHmmss` | وقت إنشاء الملاحظة. لا يتغيّر بعد ذلك أبدًا، فهو الهوية الثابتة للملاحظة و"تاريخ إنشائها". |
| type (النوع) | رمز قصير، عادةً حرف واحد | *ما نوع* هذا الشيء — مثل `T` مهمة، `N` ملاحظة، `J` يومية. قد يكون فارغًا. |
| priority (الأولوية) | `p` + رقم | مدى أهميته. البادئة `p` تتيح للتطبيقات إيجاد هذا الحقل دون لبس. |
| category (الفئة) | رمز قصير، عادةً حرف واحد | *إلى أي مجال* ينتمي (قسم، أو موضوع، أو مشروع). قد يكون فارغًا. |

يفصل `~` بين الحقول. يمكن أن يكون النوع والفئة فارغين معًا، فهذه أيضًا ملاحظة صالحة:

```text
2026_06_11-090512~~p3~.md
```

### التصادم في الثانية نفسها { #same-second-collisions }

إن كانت ملاحظتان ستحصلان على الاسم نفسه، يضيف التطبيق `-2`، `-3`، … إلى الطابع الزمني:

```text
2026_06_10-143025~N~p3~B.md
2026_06_10-143025-2~N~p3~B.md
```

تُتجاهَل هذه اللاحقة عند قراءة تاريخ الإنشاء.

### الرموز تأتي من مفرداتك { #codes-come-from-your-vocabulary }

تعني الحروف ما تقول مفرداتك إنها تعنيه:

- **دون خادم**، يحتفظ كل تطبيق بقائمته الخاصة: سطح المكتب يخزّنها لكل مجلد في
  `.knotes.json`، والهاتف في إعداداته. عدّلها بحرية.
- **مع خادم**، تنزّل تطبيقات الالتقاط المفردات: الأنواع تأتي من **الوحدات** (modules) على الخادم
  والفئات من **الأقسام المعلَّمة مرجعيًا** (bookmarked departments). بهذا تقابل حروف الملاحظة
  نوع السجل والقسم بدقة عند استيرادها. انظر [المزامنة](sync.md#vocabulary-download).

رموز الأنواع المعتادة على الخادم:

| الرمز | الوحدة | | الرمز | الوحدة |
|------|--------|-|------|--------|
| `T` | Tasks (المهام) | | `G` | Goals (الأهداف) |
| `N` | Notes (الملاحظات) | | `W` | Writings (الكتابات) |
| `J` | Journals (اليوميات) | | `R` | Resources (الموارد) |
| `P` | Planners (المخطِّطات) | | | |

## إعادة الوسم هي إعادة تسمية { #retagging-is-renaming }

تغيير نوع الملاحظة أو أولويتها أو فئتها **يعيد تسمية الملف** فحسب. يبقى الطابع الزمني، فتحافظ
الملاحظة على مكانها في الزمن. وهذا ما يجعل
[التقط الآن وصنّف لاحقًا](capture-then-classify.md) زهيد الكلفة.

!!! note "الإنشاء مقابل التحديث"
    تقرأ التطبيقات "تاريخ الإنشاء" من **الطابع الزمني في اسم الملف** و"تاريخ التحديث" من وقت تعديل
    الملف نفسه. إعادة وسم الملاحظة أو تحريرها تغيّر وقت تعديلها لكنها لا تغيّر أبدًا
    تاريخ إنشائها — ولا تستطيع أداة مزامنة ملفات تعيد كتابة أوقات التعديل أن تبعثر
    خطّك الزمني كذلك.

## أي الملفات تُعدّ ملاحظات { #which-files-count-as-notes }

القاعدة المستخدمة في *عدّ* الملاحظات واحدة في كل مكان:

- ملفات `.md` فقط،
- التي يطابق اسمها المخطط أعلاه،
- والموجودة مباشرة في المجلد (لا في المجلدات الفرعية أبدًا).

كل ما عدا ذلك إمّا يُتجاهل (الملفات النقطية، المجلدات التنظيمية، المجلدات المرافقة) أو يُعرض
كعنصر **needs metadata** (يحتاج بيانات وصفية) لتسويته.

!!! warning "حافظ على صيغة الطابع الزمني الافتراضية"
    يتيح لك سطح المكتب والهاتف تغيير نمط الطابع الزمني، لكن قاعدة العدّ المشتركة
    تتوقّع `yyyy_MM_dd-HHmmss`. الملاحظات المسمّاة بنمط آخر لن تتعرّف عليها التطبيقات الأخرى
    ولا الخادم كملاحظات قياسية.

## الصيغ القديمة { #legacy-formats }

| الصيغة | من أين جاءت | كيف تُعالَج |
|--------|--------------------|-------------------|
| `<timestamp>~p<priority>~<subjects>.txt` (عدة مواضيع موصولة بـ `-`) | إصدارات الهاتف الأولى | ما زال الهاتف يسردها ويقرؤها، ويعيد كتابتها بمخطط `.md` الحالي في المرة التالية التي تحرّر فيها إحداها. وتعرضها التطبيقات الأخرى كـ *needs metadata*. |
| أي ملف `.md` أو `.txt` باسم حر | وضعه برنامج آخر | الهاتف: يُسرد دون وسوم، ويُدار بمجرد تحريره. سطح المكتب: *needs metadata*؛ وتسويته تعيد تسميته وفق المخطط، وتحتفظ باسمه الأصلي سطرًا أول، وتؤرّخه بوقت تعديل الملف نفسه. |
| أي ملف أو مجلد آخر | تنزيلات، تصديرات، مسح ضوئي | سطح المكتب: تسويته تنشئ ملاحظة جديدة وتنقل العنصر إلى [المجلد المرافق](companion-folders.md) لتلك الملاحظة. |

## كيف يقرأ كل تطبيق الاسم { #how-each-app-reads-the-name }

| التطبيق | السلوك |
|-----|-----------|
| [الهاتف](../mobile/index.md) | يقرأ كل الملاحظات القياسية إضافة إلى ملفات `.txt` القديمة. لوحة تصفية بأوجه النوع / الأولوية / الفئة، إضافة إلى طابورَي تنظيف: **الأسماء غير القياسية** و**التصنيف الخاطئ** (اسم سليم البنية يستخدم رمزًا لا تعرّفه مفرداتك). |
| [سطح المكتب](../desktop/index.md) | لوحة وكانبان مجمّعان حسب الوسوم الثلاثة. `Ctrl+Shift+<letter>` يعيد وسم الملاحظة المحدّدة؛ و`Ctrl+Shift+<digit>` يضبط أولويتها. وطابورا التنظيف نفسهما في الشريط الجانبي. |
| [الطرفية](../terminal/index.md) | تستخدم شيفرة التخزين الخاصة بسطح المكتب. سطر مثل `t3d buy milk` يحفظ ملاحظة نوعها `t` وأولويتها `3` وفئتها `d`. |
| [تطبيق الويب](../web/index.md) | تقرأ صفحة **Local notes** (الملاحظات المحلية) مجلد الملاحظات على قرص الخادم. وحين تكتب ملاحظة هناك، يُؤخذ حرف فئتها من أول وسم `#X.something` في الملاحظة. |
| الاستيراد إلى الخادم | يحتاج نوعًا من حرف واحد يطابق وحدة وفئةً غير فارغة؛ ويأخذ التاريخ من الطابع الزمني والأولوية من رمز `p`. |

!!! tip "ترتيب الوسوم على الشاشة"
    يعرض سطح المكتب وسوم الملاحظة بالترتيب **النوع · الأولوية · الفئة** (مثل `T 2 A`) — وهو
    الترتيب نفسه في اسم الملف — ويبقيها من اليسار إلى اليمين حتى في الملاحظة العربية.
